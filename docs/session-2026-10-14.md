# 2026-10-14 会话记录：从压测 503 到本地评分体系

> 一句话：**修掉了压测的 503（rerank 物理 batch 是隐形上限），修好了评测口径（锚点前缀骗了旧判据），
> 建起能给平台分数对齐的本地评分流程（±2 分），并把 71.27 这一轮归因到实例级证据。**

## 一、起因：专家压测发现崩溃

- 现象：`logs/memorysum.log` 2026-10-14 05:26–05:38Z 共 **23 次 `/search` 503**，全部是**同一条**
  9050 字符 query（打到只有 1 条消息的 scope），每次卡 **3027 ms**（= 3 次尝试 + 1s/2s 退避）。
- 根因（llama.cpp 日志 + 源码 `server-context.cpp:3157`）：rerank 启动参数 `-ub 2048`，而
  `--pooling rank` 让 `slot.can_split()` 恒为 false → **每对 (query, document) 必须整体进一个物理
  batch**；3648 token 的 pair 被 `HTTP 500 input (3648 tokens) is too large to process`。
  而配置里 `reranker.single_pair_proxy_tokens = 8192` 才是管线以为的上限 → **服务端与配置不一致**。
- 修复：rerank 改 `-c 8192 -b 8192 -ub 8192`（llama.cpp 会把 slot 上下文压回模型训练窗口 8192
  并告警，所以 8192 是天花板）；同一请求复测 **200 / 289 ms**；停机 1.2 s；显存 900 → 1046 MB。

## 二、为"彻底稳定"做的加固（都被实测约束）

| 改动 | 依据 |
|---|---|
| 单对预算 8192 → **4608** | 标定实测（`scripts/calibrate_rerank_tokens.py`，1330 条真实 memory + 对抗样本）：代理分词器 tiktoken 对 XLM-R 的**低估最坏 1.479**（英文/URL/标点那侧）→ 4608×1.479≈6814 < 8192，留 17% 余量 |
| query 上限搬进 config | 原来是硬编码 6144（违反"参数可审计"） |
| 超限输入**快速失败** | `_post_json` 认出 llama.cpp 三类容量错误 → 立刻 `model_provider_input_too_large`（9 ms），不再空转 1+2 秒 |
| "所有候选都超预算"→ 融合排序 | 旧代码返回 `data=[]`（让调用方以为"没有相关记忆"），现在返回融合排序 + WARNING |
| 并发实测 | 4×3570、6×3570、**8×6970** token（合计 55.7k，远超 8192 unified KV）—— **零 500**，只是排队（p50 3.3 s / max 5.8 s） |

**明确否决**（都有实测）：空白/转义压缩（真实 token **0.0%** 节省、tiktoken 口径 1.4%，记录数/覆盖率
不变）；`-ub 16384`（+576 MB 显存、无收益）；邻居扩展（+1.6pp 饱和）。

## 三、评测体系：专家只给 add+search 时的本地评分

**约束**：专家不提供题集、金答案、评分标准、实例清单 —— 只能靠 `/add` + `/search` 流量。
**可用信号**（每轮自动可抽 ~17 条）：赛道标签 `[<suite>][session_N][D…]`（11）、逐题判定
`Streaming online QA feedback`（4）、流式任务自评 `trajectory.task_index/score`（2）。

**本地判据（冻结，4 条）**：① 精确值题要求原样可读且与 as-of 吻合；② 时间题只有相对时间而无可换算
锚点 → 0；③ 选择题需决定性证据（仅相关片段 → 0.5）；④ 不依赖记忆的题按平台模型能否答对判
（短建议 1.0、长历史综合 0.0，用官方 E1=100/F1=0 校准）。附 `blame` 归因字段。

**两个口径**（关键修正）：
- ① **证据充分性**＝41 题按题等权 → 上界（实测偏高 5~8 分）；
- ② **能力树口径**＝按子能力等权 + 观测不到的 5 片（C3/D2/E2/G2/I1）代入平台值 → **能与平台对话**
  （平台总分 ≈ 其叶子均值 ±1.2）。实测精度 **±2 分**（本轮 72.23 vs 71.27）。

**修掉的判据 bug**：旧判据要求"正文前 100 字符是 gold 逐字子串"，锚点上线后把 top-1 从 38/60 砸到
13/60（而精排名次没变：`attach_anchor` 改恒等 → MRR 0.166 → 0.718）→ 改成"正文含 ≥60 字符逐字
片段"，并同时报平台的 `ids_all` 口径。**结论：指标腰斩先做"检索→融合→精排→输出"链路追踪。**

**统计事实**：平台自身两轮差 **0.97**（C1 53.33↔60、C2 60↔80 是唯一会跳的两片）；40 题只能检测
>8% 效应；我们同题同内容重灌一轮 top-1 有 **12%** 翻转（本地 embedding 非确定性）。
