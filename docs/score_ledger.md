**为什么说归因不明 —— 逐条排除**：

| 候选原因 | 排查 | 结论 |
|---|---|---|
| 422 修复 | 本轮窗口 **0 个 422**；上一轮（11:42-12:04）**也是 0 个** | ✗ 不是它 |
| 候选组数 64→100 | G4 对应题的 `rerank_groups` 实测 **42 < 64** | ✗ 不受该上限约束 |
| pair 预算 24000→48000 | 同题组数 42 × 单组 ~900 token ≈ 9.9k，**远低于 24000** | ✗ |
| `output_records` 64→100 | 该题返回 11~18 条，**远低于 64** | ✗ |
| `output_tokens` 32768→65536 | 响应 ≈3.5k token，**远低于 32768** | ✗ |

**排除完只剩两种可能**：① 平台侧判定发生变化（G4 只有 2 个判定点，50%→100% 就是**一个点**翻转）；
② 某种我们尚未追踪的交互。**qa_feedback 只覆盖 streaming（I1/I2），不覆盖 G4，所以拿不到实例级证据。**

**教训（写给下一次）**：
- 平台分数是**离散判定点的集合**，不是连续量 —— **单个判定点翻转就能带来 +4.6**。
  我按"本地 +1 题 × 0.2 传递率"预测 71.0，实际 74.90，**低估 3.9**。
  **下次预测要用"判定点"为单位，而不是按比例外推。**
- **不要因为总分涨了 4.6 就认定是自己的改动生效** —— 本轮 G4 的机制链是**断的**。
  真正能证明因果的只有"实例级证据 + 反事实核对"（就像时间锚点那次）。
