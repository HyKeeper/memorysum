Secrets do not appear in email, public rankings, or public API responses. 04 Endpoint security The platform connects only to network-validated public HTTP(S) endpoints and rejects URLs with embedded credentials or targets resolving to private, loopback, or link-local addresses. 05 Process audit The platform retains request outcomes, latency, errors, returned memories, and contract-validation evidence required to verify evaluation integrity and public eligibility. 06 Result visibility Private jobs and results are visible only to the bound Leaderboard API Key. The public board shows approved systems, versions, scores, and required evaluation metadata. Participant data-handling obligations Evaluation data and derived copies may be used only to complete the current job. Do not use them for training, fine-tuning, product analytics, dataset reconstruction, or redistribution. Runtime Rules These limits and retry rules are part of the public evaluation contract. Authentication Add and Search support Token, Bearer, or X-Api-Key authentication. Health checks use an unauthenticated GET and accept any 2xx response. No silent API truncation The API contract sets no single global character cap. Add and Search payloads and archived responses are not silently shortened; unsupported payloads should receive a clear 4xx response. Answer context budget The shared 128,000-token Answer window reserves 8,192 output tokens and 2,048 safety tokens, leaving 117,760 input tokens. If needed, Answer keeps a token-counted prefix of Search candidates in returned rank order; the question, options, instructions, and archived Search response remain intact. Add retries 408, 409, 425, 429, 500, 502, 503, 504, and 524 are retryable, with at most 32 request attempts. The same logical write keeps the same request_id and payload. Search retries 408, 425, 429, 500, 502, 503, and 504 use bounded exponential backoff. Search 409 and other permanent 4xx responses fail without retry. Rate limits For HTTP 429, the platform honors a valid Retry-After value up to 60 seconds; when absent, it waits 60 seconds. Advertised concurrency is an upper bound, not a guaranteed request rate. Failure responses Use 400 or 422 for invalid payloads, 401 for invalid credentials, and 403 for a forbidden user scope. A 2xx response with a malformed body still fails contract validation.
